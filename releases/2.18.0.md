2.17.0 이후 추가된 **Jira·Confluence 연결과 Jira 업무 관리**를 정리한 릴리즈입니다. 최소 지원 버전은 **Obsidian Desktop 1.11.5**입니다. 기존 노트·To-Do·설정을 유지하며, Atlassian 연결은 선택 기능이고 기본은 비활성입니다.

## 새 기능

### Jira·Confluence 계정 연결

- 설정의 **Jira·Confluence 연결**을 켜고 회사 계정으로 로그인합니다. 별도 API 토큰이나 OAuth JSON을 붙여 넣지 않습니다. 회사 정책에 따라 관리자 승인이 필요할 수 있습니다.
- 사용할 사이트를 선택하고 **연결 테스트**를 실행합니다. Jira와 Confluence 각각 실제 업무·문서 읽기에 성공했는지 표시합니다.
- 로그인 정보 저장, 현재 연결 성공, 이전 테스트 이력, 검색 결과 없음, 접근 권한·네트워크 오류를 구분합니다.
- 최근 자료가 없는 경우 접근 가능한 업무·문서 링크로 개별 테스트할 수 있습니다. 재연결·연결 해제와 안전한 오류 안내를 제공합니다.

### Jira 원본 자동 연결과 함께 갱신

- Atlassian 연결과 Jira 동기화가 켜져 있으면 티켓 수동 갱신·정기 자동 갱신 시 Jira도 함께 조회합니다. Jira 조회 실패가 ServiceNow 갱신 전체를 막지 않도록 분리했습니다.
- Jira 화면을 열면 저장된 자료를 먼저 보여주고 최신 자료를 자동으로 가져옵니다. 동시에 발생한 같은 조회는 합쳐 처리합니다.
- 티켓 번호가 일치하는 하위 업무를 실제 상위 관계로 묶어 원본 업무를 찾습니다. 메인 에픽이 하나로 확인되면 자동 연결하고, 실제 원본 후보가 여러 개일 때만 사용자에게 선택을 요청합니다.
- 기존 수동 연결은 유지합니다. 후보는 같은 너비의 세로 목록과 상세 미리보기로 확인하며, 다른 번호·제목·Jira 링크로 직접 검색해 연결할 수도 있습니다.

### 업무 기록·댓글 통합 창

- 티켓의 **업무 기록·댓글**에서 **ServiceNow 워크노트 / Jira 댓글** 탭을 전환합니다. Jira 업무 화면에서도 같은 기록 패널을 사용합니다.
- Jira 원본과 하위 업무의 접근 가능한 댓글을 모두 가져오고, 여러 업무를 선택해 함께 보거나 전체 선택·해제합니다. 검색·기간·대화 시간순으로 좁혀 볼 수 있습니다.
- 업무 선택 목록에 **담당자·보고자·계획 시작일**을 표시해 제목이 같은 업무도 구분합니다. 시작일은 설정한 필드명/ID를 사용하며 기본은 `Plan Start Date`입니다.
- 원본 업무·작성자·작성/수정 시각과 내부·제한 댓글 표시를 유지합니다. 지원되는 Jira 이미지는 로컬 assets에 보관합니다. 위치를 확인할 수 없는 이미지는 별도 갤러리로 표시합니다.

### 원댓글·답글 대화 표시

- Jira에서 제공하는 부모 댓글 정보로 **원댓글 아래에 답글**을 묶고, 들여쓰기·연결선·답글 대상을 표시합니다.
- 대화는 최근 답글·댓글 순 또는 오래된 대화 순으로 정렬하며, 대화 안에서는 원댓글부터 작성 순서대로 읽습니다.
- 페이지를 이동해도 원댓글과 답글이 따로 떨어지지 않습니다. 답글만 검색·기간 조건에 맞으면 원댓글 등 대화 맥락을 함께 보여주고 조건 밖의 항목임을 표시합니다.
- 부모 댓글이 없거나 연결 정보가 잘못된 경우에도 확인 가능한 댓글을 숨기지 않고 안내합니다. 멘션이나 가까운 시각만으로 답글 관계를 추정하지 않습니다.

### 자동 번역과 댓글 아래 입력

- **표시 언어를 한국어·영어로 바꾸면 현재 페이지의 미번역 댓글을 자동 번역**합니다. 페이지·필터·원문 변경에도 필요한 부분만 번역하고 기존 번역은 재사용합니다.
- 원문 보기, 진행 상태와 실패 시 재시도를 제공합니다. 늦게 도착한 결과가 수정된 댓글이나 다른 사이트에 잘못 적용되지 않도록 했습니다.
- 각 댓글 아래 **댓글 달기**로 입력창을 열면 해당 업무가 자동 지정됩니다. 업무를 다시 고르지 않으며, 새로고침·번역·필터 변경 중에도 댓글별 초안과 커서를 유지합니다.
- 한국어 초안은 **영어로 번역**한 뒤 최종 대상·언어·본문을 검토할 수 있습니다. 번역이나 입력만으로 Jira에 전송하지 않습니다.
- 현재 연결 방식의 등록은 **선택한 업무에 새 댓글 추가**입니다. 기존 답글 관계를 화면에 표시하는 기능과는 별개이며 원댓글 편집이나 Jira의 네이티브 대댓글 등록을 뜻하지 않습니다.

### Jira 일정으로 To-Do 생성

- **일정 생성** 창에서 **DS 문서 / Jira** 탭을 선택합니다. Jira 업무 화면에서도 같은 일정 패널을 사용합니다.
- Jira 일정을 최신 자료로 다시 조회한 뒤 원하는 하위 업무를 선택합니다. 담당자·보고자·시작일·기한을 함께 확인하고 시작일 또는 기한을 완료 예정일의 기준으로 선택합니다.
- 활성화된 로컬 To-Do 상태만 선택합니다. 날짜만 있는 값에는 생성 시각을 적용하고, 없는 일정은 임의로 만들지 않습니다.
- Jira 원본 식별자로 중복 가져오기를 방지하며 수동 To-Do를 덮어쓰지 않습니다. To-Do 생성은 로컬 작업이고 Jira 업무를 생성하거나 변경하지 않습니다.

### 사람이 확인한 Jira 변경

- 기본 연결과 자동 갱신은 읽기 전용입니다. 직접 수정은 별도 설정과 **추가 OAuth 쓰기 동의**가 있어야 사용할 수 있습니다.
- 현재 지원 범위는 **새 댓글 등록, 허용된 상태 전환, 기한 변경**입니다. 담당자 등 모든 Jira 필드를 편집하는 기능은 아닙니다. Confluence는 조회 전용입니다.
- 요청마다 정확한 업무와 댓글 언어·본문 또는 변경 전후 값을 확인하고 사용자가 직접 확정합니다. 필터·보기 선택만으로 등록 대상을 바꾸거나 자동 변경하지 않습니다.
- 원댓글의 역할·그룹 공개 제한 및 내부 댓글 범위를 보존하고 전송 전에 다시 확인합니다. 추가 필수 입력이 필요한 상태 전환은 Jira에서 진행하도록 안내합니다.
- 결과가 불확실한 변경은 자동 재시도하지 않고 추가 변경을 잠급니다. 원본 Jira 확인 후 진행하여 중복 등록을 방지합니다.

### AI 티켓 분석 자료 보강

- 분석 프롬프트에 **Jira 원본·하위 업무 구조**를 먼저 제시하고, ServiceNow 워크노트와 Jira 댓글을 **출처가 구분된 시간순 기록**으로 연결합니다.
- 내부·제한 댓글은 기본 외부 AI 프롬프트에서 제외합니다. 일부만 조회됐거나 저장된 자료를 사용하는 경우 이를 표시합니다.
- 복사는 클립보드에만 적용되며 외부 AI에 자동 전송하지 않습니다. 전달 전 회사의 정보 공유 기준에 맞는지 확인해야 합니다.

## 개선 및 수정

- Jira 언어 선택이 표시만 바꾸고 번역 요청을 실행하지 않던 문제를 수정했습니다.
- 댓글 위의 업무 선택 입력 대신 원댓글 아래 입력을 제공하고, 등록 언어·번역·등록 전 확인 버튼의 높이와 기준선을 통일했습니다.
- 좁은 화면에서는 댓글 입력 버튼을 그룹으로 줄바꿈하고 입력 동작 영역을 유지합니다.
- ServiceNow 워크노트 검색·정렬·유형·언어 필터와 시작일·종료일을 실제 컨테이너 폭에 맞게 배치해 날짜 값·달력·현재 시간 버튼이 가려지지 않도록 했습니다.
- Jira 연결 테스트의 조회 기간을 제한하고, 검색 조건 거부를 로그인·권한 오류와 구분해 안내합니다.
- 조회 결과의 상위 관계·상태 식별 정보가 축약되어 원본 업무를 잘못 판단할 수 있던 응답 처리와 오래된 미검색 캐시 문제를 보완했습니다.

## 업데이트 방법

1. 중요한 Vault 노트와 플러그인 설정을 백업합니다.
2. Community plugins에서 업데이트하거나 릴리즈의 `main.js`, `manifest.json`, `styles.css` **세 파일만** 교체합니다.
3. **`data.json`, `organization-pack.json`, `ticket-activity.json`과 기존 Jira 캐시·업무 자료를 삭제하거나 덮어쓰지 않습니다.**
4. 플러그인 또는 Obsidian을 다시 시작합니다. Atlassian을 쓰지 않는 사용자는 기존 기능을 그대로 사용합니다.
5. 사용할 경우 설정에서 Atlassian 로그인·사이트·제품별 연결 테스트를 확인합니다. 댓글 번역에는 기존 Translate 플러그인과 번역 제공자 설정이 필요합니다.
6. 직접 Jira를 수정하려면 추가 동의 후 대상·변경 내용을 확인합니다. 실제 업무 변경이 필요하지 않다면 읽기 전용으로 유지합니다.

## 보안·범위 및 검증 경계

- 인증 정보는 Obsidian SecretStorage를 사용합니다. 업무가이드팩·인증 토큰·OAuth JSON·개인 설정·고객 자료는 공개 릴리즈에 포함하지 않습니다.
- Jira 댓글·이미지·번역과 로컬 캐시는 Vault에 저장되는 업무 자료입니다. Vault의 접근·백업·동기화·보존 정책을 적용해야 합니다. 연결 해제가 기존 자료를 자동 삭제하지는 않습니다.
- 계정 연결이 회사 권한이나 관리자 정책을 우회하지 않습니다. 사용자가 접근 가능한 자료만 조회합니다.
- Jira만으로 새 원본 티켓을 등록하는 기능, 모든 Jira 필드의 편집, Confluence 게시·수정은 이번 범위가 아닙니다.
- 자동 검사는 모의 제공자·응답·변경을 사용하며 실제 Jira 댓글·상태·기한을 변경하지 않습니다. 실제 계정 연결·번역 제공자·업무 변경의 성공을 자동 검사만으로 보증하지 않습니다.
